# GRI Design Bench 测什么，研究怎样闭环

**项目的目标是评估 Agent 能否用有限的模拟证据，作出可复核的配方研发决定。** 研究者要决定一项响应式释药设计是否值得进一步表征，以及下一项验证应排除哪种失败。虚拟患者中的数值指标是这些决定的证据。

| 现有部分 | 能测到什么 | 对研究的用途 |
|---|---|---|
| v0.2 配方设计任务 | 通过终端调用模拟器、用有限计算搜索参数、遵守约束、交付在新进餐情景中仍表现良好的候选 | 建立受约束搜索的能力基线。总分同时受工具调用、搜索和验证影响，单独一张榜无法确定改进来自哪一步 |
| Harbor 等剂量时序任务 | 正确构造配对反事实、保持逐日剂量、计算并交付可复算的指标 | 核查响应配方的模拟收益是否随日内时序改变。分析方案由任务给定，因此这一关主要测科研计算和复现 |
| 追加证据与研发决定 | 现阶段用程序化规则演示。以后可以固定候选和预算，测 Agent 是否会提出可证伪的预测、选取有价值的验证、据结果修正决定 | 给研究者一份有证据支持的候选去留判断，指出它依赖的情景和待核实的材料性质 |

## 两种改善怎样区分

**模型和 Agent 的改善。** Benchmark 给出可重复的诊断。比如，两个系统都能找到高 TIR 的候选，但只有一个会在漏餐证据推翻判断时暂缓推进。要证明系统改进，需要保留同一信息与预算，对照改动前后的系统，查看未见任务上失败是否减少、误推进是否减少，以及是否错过更多有价值的候选。一次评分本身只测量当下表现。

**科研流程的改善。** 研究者可拿到带对照的结果、失败情景和下一项验证的理由。比如，若缺餐时仍有较高释放导致低血糖指标恶化，下一步可以优先检查基础泄漏是否有足够的体外证据。只有获得新的材料或生理证据，才有依据更新外推判断。当前产物用于体外及模拟研究的优先级排序，人体给药仍需临床证据。 [模型与材料假设](SCIENTIFIC_SCOPE.md)

## 一轮闭环如何验收

1. **提出问题并记录初判。** 固定候选与对照，记录预期收益、失败条件、是否值得进一步表征。
2. **按预算追加证据。** 在相同候选、可见信息与预算下，比较固定验证流程与能够按案例分配验证的流程。每次查询和结果都可核对。
3. **用证据修正决定。** 提交推进或暂缓的选择、支持证据和失败原因。即使维持原决定，也可核对理由是否与结果一致。
4. **独立复核。** 在决定锁定后评估未见情景，分别记录错误推进、错过应推进候选和资源消耗。科学指标可程序化核对，理由供研究者审阅。
5. **让复核改变下一轮。** 如果一个固定流程已经达到同样结果，研究者直接复用它。若某类错误持续出现，就修改研究流程或 Agent 工具，并在新的面板上复核。同样，实测数据推翻模拟假设时，应更新模型及其任务边界。

前一轮进餐验证中，追加证据把与独立面板的一致数从 5/6 提到 6/6，两种同预算流程都纠正了同一个初判。 [进餐验证](../results/decision-study-2026-11-13/README.md)

本轮把基础泄漏和响应延迟纳入候选去留。在 24 种模拟材料状态中，固定测泄漏找回了独立面板支持的两个状态，逐例选择取得相同结果。下一轮的研究输入应是低糖释放及剩余储量的实测数据，用其不确定性检验候选是否仍值得推进。现有数据支持研究流程改进，尚未触发 Agent 对照。 [材料验证结果与下一项实验](../results/material-validation-2026-11-13/README.md)

## 与 Terminal-Bench-Science 的关系

上游提出的闭环是领域专家贡献真实工作流程，实验室用任务定位和改进 Agent，改进后的工具再进入科研流程。本项目可以提供其中一环，给出释药研究中可重复验证的任务和失败案例。现有 Harbor 任务已验证程序化验收与独立复算。是否能区分模型的科研判断，要先证明有实质性的决策差异，再用同信息、同预算的固定流程作参照。 [Terminal-Bench-Science 官方贡献说明](https://www.terminal-bench-science.ai/contribute) · [现有 Harbor 任务](../harbor/release-timing-attribution/README.md)
