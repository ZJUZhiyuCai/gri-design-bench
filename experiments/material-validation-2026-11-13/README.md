# 基础泄漏和响应延迟的追加验证

研究决定是是否值得把一个响应式释药候选送去进一步体外表征。先对同一候选的不同材料状态建立模拟证据，再问只够补一项验证时，测基础泄漏或测响应延迟会不会改变候选去留。用新的进餐面板验收已经锁定的决定。 [运行前规则](protocol.json)

## 参数依据

本地核对了 Xu 等的原始工作簿和历史拟合文件摘要。Fig. 2i 是 i-crystal-1 在 0、100、200、400 mg/dL 下的累积释药曲线，0–70 分钟每 10 分钟采样，每个浓度三条重复，共 96 个读数。相对基础泄漏是模型中的无量纲参数 `r_b/r_max`，本轮取历史重复轨迹 bootstrap 区间两端的近似值 **1.53 和 2.33**。这一区间依赖 Hill 形状、启动干扰项和误差假设。零葡萄糖数据支持非零基础释放，正常低糖下的测量还包含残余葡萄糖响应，需要已知的响应幅度及形状来解释。 [Xu 等 Fig. 2 与数据入口](https://www.nature.com/articles/s41565-025-01860-0/figures/2) · [原始工作簿](https://static-content.springer.com/esm/art%3A10.1038%2Fs41565-025-01860-0/MediaObjects/41565_2025_1860_MOESM5_ESM.xlsx) · [历史边界依据](../../docs/BOUND_PROVENANCE.md)

同一历史条件拟合的时间常数支持范围约为 0.1–10 分钟，快端触及拟合下界。**2 和 10 分钟**用于比较较快和较慢的模型响应，2 分钟在历史重复拟合范围内，10 分钟是条件 profile 上端。它们是有文献约束的模拟假设，未由阶跃数据直接测定。拟合的共同试验启动偏移未用于本轮。Fig. 2j 是另一制剂 i-crystal-3 的 24 小时交替数据，不能补足 i-crystal-1 的分钟分辨率。另一种葡萄糖响应复合物的原始研究给出了交替葡萄糖体外测定的先例。 [Xu 等 Fig. 2](https://www.nature.com/articles/s41565-025-01860-0/figures/2) · [Zhang 等，Fig. 1f–g](https://pmc.ncbi.nlm.nih.gov/articles/PMC11153331/)

## 如何比较

- 六个已见开发患者组各有一个历史固定设计。把两种泄漏与两种延迟完全交叉，其他参数固定，历史名义参数另外重算。四种组合是等权压力情景。每项扰动都用自己的逐日等剂量匀速重放来估计时序收益。跨状态保持释放幅度和储量固定，实际递送量仍可能因泄漏改变。报告同时记录递送量与储库耗尽。
- 以四个新进餐种子、三类变体建立规划表。追加一项模拟验证只会揭示泄漏或延迟的二元类别。完美读数和等成本是用来判断信息价值的乐观假设。基线包括不追加、固定测泄漏、固定测延迟，以及使用同一张规划表逐例选择。两项全测提供更高预算诊断。
- 初判与追加后决定采用同一个推进规则。候选的平均 TIR 相对等日剂量重放至少增加 5 个百分点，平均 TBR70 不增加，且所有响应轨迹通过旧协议的三项低血糖门槛。0 和 10 个百分点只用于敏感性检查。这是研发筛选规则。
- 决策写入后，才在八个新种子及三类变体上复算。误推进指新面板不支持但流程仍选中，漏选指新面板支持但流程暂缓。决策以病例和材料状态为单位，同一病例的状态共享患者。两类验证必须在不同病例有可复核的优势，逐例流程才有理由与 Agent 比较。
